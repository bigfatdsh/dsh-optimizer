# dsh-optimizer —— 优化插件集

**把省 token 的开关收在一个「优化」面板里。** 输入栏右侧（模型选择器左边）一个「优化」图标，
点开是开关面板；再点图标 / 按 Esc / 点面板外收起。开关改动的**下一个模型步骤**就生效。

当前含一个开关：

| 开关 | 作用 |
| --- | --- |
| 精简化输出 | 在系统提示词最后追加一段输出纪律：零开场白、零复述、零装饰性小节，只留事实、代码、命令、路径、风险与下一步。**任务内容一个字不改。** |

以后新增省 token 的开关，按下面"加一个开关"那节实现同一个约定即可进面板，不需要改本插件。

## 为什么这样省 token 而不动任务

提示词段落是"生成前约束"，不是"生成后裁剪"。模型写文件、跑命令、装文档时走的路与不装
插件时完全一致；被省掉的只有它本来会写、而你没在看的那些字。

关闭时段落返回空串，宿主把整段丢掉——**关掉就是零成本**。

## 代价：一次前缀缓存失效

段落恒定在提示词末尾，开关不变时逐字节稳定，不产生额外缓存失效。只有你**主动**拨开关
的那一次，会从这一段起重新计费一次。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `conciseDefault` | `false` | 首次装配的默认值；之后以状态文件为准 |
| `persist` | `true` | 界面开关写到 `<DSH_HOME>/optimizer.json`，重启后保持 |
| `log` | `false` | 每次装配打一行 info 日志 |
| `file` | 空 | 状态文件路径；留空用默认位置 |

未知键会被**严格拒绝**（配置写错当场报错，不会静默失效）。

## 诊断端点

| 方法 | 作用 |
| --- | --- |
| `GET /dsh-optimizer` | 开关状态、开关登记表、生效配置、装配统计 |
| `POST /dsh-optimizer { "enabled": boolean }` | 开关（兼容旧字段名 `concise`） |
| 其它方法 | `405`；坏请求体 `400` |

## 加一个开关 = 不用改这个插件一行代码

面板从 `GET /dsh-optimizer` 的 `switches` 字段读登记表，每项描述一个开关：

```json
{ "id": "concise", "label": { "zh": "精简化输出", "en": "Concise output" },
  "hint": { "zh": "…", "en": "…" }, "endpoint": "/dsh-optimizer", "field": "enabled" }
```

任何插件只要实现同一个约定就会出现在面板里：

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `<endpoint>` | — | `{ "enabled": boolean }` |
| POST | `<endpoint>` | `{ "enabled": boolean }` | `{ "enabled": boolean }` |

读不到（没装、404、返回垃圾）的开关直接不显示，不会出现"点了没反应"的项。

## 段落名必须唯一（踩过的坑）

段落注册在 `optimizer:concise`。**名字不能借用别的插件的**：与仍在装的插件撞名时，
宿主会拒绝这次注册，整个插件被静默丢弃——症状是路由 404、界面图标消失（真实踩过）。

## 失败方向

状态读不出、盘写不了、端点注册失败，一律退回"原样工作"：读坏保持默认值、写盘失败只
记日志、注册失败不影响段落注入。**不会让模型收到半截指令，也不会让宿主拒绝启动。**

## 验证

- `npm test` —— 插件与浏览器半边的契约测试（19 条）
- `npm run verify` —— 客户端 bundle 纯度闸门（一旦违反，整个页面打不开）
