# dsh-optimizer —— 优化插件集

**把省 token 的开关收在一个「优化」面板里。** 输入栏右侧（模型选择器左边）一个「优化」图标，
点开是开关面板；再点图标 / 按 Esc / 点面板外收起。开关改动的**下一个模型步骤**就生效。

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 推理等级 auto | **开** | 每个请求按轻重自动选推理档位：闲聊与轻活少想，重活多想。落成该模型**真实支持**的档位；模型不支持、目录查不到、判定出错，一律原样透传。**你在模型选择器里手选的档位永远优先。** |
| 精简化输出 | 关 | 在系统提示词最后追加一段输出纪律：零开场白、零复述、零装饰性小节，只留事实、代码、命令、路径、风险与下一步。**任务内容一个字不改。** |

以后新增省 token 的开关，按下面"加一个开关"那节实现同一个约定即可进面板。

## 推理等级 auto：判定表

| 组 | 典型输入 | 落到 DeepSeek 四档时 |
| --- | --- | --- |
| quiet | 「你好」「谢谢」这类纯客套，且整句很短 | `off` |
| light | 提问、解释、看文件、总结 | `low` |
| standard | 改代码、转格式、写脚本、排查报错 | `high` |
| heavy | 架构设计、整套重写、全面审查 | `max` |

档位更少的模型自动合并：三档（low/medium/high）→ 轻活到中档、中活与重活共享顶档；
两档（low/high）→ quiet/light 走低档、standard/heavy 走高档。档位与组无关，只看该模型
**声明支持**哪些；一个都不支持就完全不动。

短追问（「继续」「那这个呢」）继承上一轮的组，且重活不会被继承成轻活。

## 为什么省 token 而不伤质量

- **精简化**：提示词段落是"生成前约束"，不是"生成后裁剪"。模型写文件、跑命令、装文档时
  走的路与不装插件时完全一致，被省掉的只有它本来会写、而你没在看的那些字。关闭时返回
  空串，宿主把整段丢掉——**关掉就是零成本**。
- **推理等级**：省下来的是**思考预算**，不是任务本身。轻活本来就不需要长推理；判错成重活
  只是多花一点思考。判错成轻活的风险用两条规则兜住：(1) 要动手、要读东西的活最省也停在
  `low`，不会被压到 `off`；(2) 出现出问题 / 大工程 / 长文本信号时分数直接把档位抬上去。
  判定是纯字符串规则，每个 turn 跑一次，微秒级，**不额外发请求、不额外花 token**。

## 它挂在哪儿（以及刻意不挂哪儿）

推理等级只挂两个宿主公开的契约事件：

- `agent/pre-step` —— 每个 turn 的起点，拿这一步真正要进模型的用户消息判组；
- `agent/request` —— 拿这次调用的完整配置，写回 `reasoningEffort`。

两者都是"读参数、调 `next()`"的形态。**不包任何模型调用路径、不改模型目录、不改模型
选择器的 DOM**——早期版本正是这些做法把宿主内存拖爆的。

## 代价：一次前缀缓存失效

精简化段落恒定在提示词末尾，开关不变时逐字节稳定，不产生额外缓存失效。只有你**主动**
拨开关的那一次，会从这一段起重新计费一次。推理等级改的是请求头里的档位字段，不动提示词。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `autoDefault` | `true` | 推理等级 auto 首次装配的默认值 |
| `conciseDefault` | `false` | 精简化首次装配的默认值 |
| `persist` | `true` | 界面开关写到 `<DSH_HOME>/optimizer.json`，重启后保持 |
| `log` | `false` | 每次判定/装配打一行 info 日志 |
| `file` | 空 | 状态文件路径；留空用默认位置 |
| `force` | 空 | 写死一个档位，跳过判定；该模型不支持时忽略 |
| `levels` | 空 | 单项覆盖：`{ heavy: 'max' }` |

未知键会被**严格拒绝**（配置写错当场报错，不会静默失效）。

## 诊断端点

| 方法 | 作用 |
| --- | --- |
| `GET /dsh-optimizer` | 两个开关状态、开关登记表、生效配置、装配统计 |
| `GET /dsh-optimizer?diag=1` | 追加：每轮判定次数、组分布、最近 20 条落地记录、在记会话数 |
| `POST /dsh-optimizer { "auto": boolean }` | 推理等级开关 |
| `POST /dsh-optimizer { "enabled": boolean }` | 精简化开关（兼容旧字段名 `concise`） |
| 其它方法 | `405`；坏请求体 `400` |

`diag=1` 是排查"到底生效没生效"的唯一入口：`effort.recent` 里每条 `apply` 记录都带
`bucket` / `model` / `from` / `to`。

## 加一个开关 = 不用改这个插件一行代码

面板从 `GET /dsh-optimizer` 的 `switches` 字段读登记表，每项描述一个开关：

```json
{ "id": "concise", "label": { "zh": "精简化输出", "en": "Concise output" },
  "hint": { "zh": "…", "en": "…" }, "endpoint": "/dsh-optimizer", "field": "enabled" }
```

`field` 决定读哪个字段，所以一个端点可以挂多个开关（本插件两个开关就是这样共存的）。
读不到（没装、404、返回垃圾）的开关直接不显示，不会出现"点了没反应"的项。

## 失败方向

| 情况 | 行为 |
| --- | --- |
| 模型不支持推理 | 不改，透传 |
| 模型目录取不到 / 抛错 | 不改，记警告（目录缓存 1 分钟后重试） |
| 判定或写回时抛异常 | 不改，透传，计数 +1 |
| 提示词段落名字被占用 | 只丢段落，推理等级照常工作（注册类动作全部经过 `guard()`） |
| 端点注册失败 | 没有开关面板，判定与落地照常 |
| 状态文件读坏 | 保持默认值，记一条警告 |
| 状态文件写不进 | 只记警告，内存值照旧 |

**不会让模型收到半截指令，也不会让宿主拒绝启动。**

## 验证

- `npm test` —— 判定表 + 档位落地 + 插件契约 + 浏览器半边（47 条）
- `npm run verify` —— 客户端 bundle 纯度闸门（一旦违反，整个页面打不开）

## 已知边界

- 自动档位不写回模型选择器，界面上显示的仍是那个会被改写的档位；真实生效值以会话日志
  里的 `request/header` 或 `?diag=1` 的 `recent` 为准。
- 会话中途重启插件时，第一轮按"用户手选优先"保守处理（那一轮不动档位），之后恢复。
- 每个会话一条判定记录（只存组名与档位 id，上限 64 条），会话销毁即释放。
