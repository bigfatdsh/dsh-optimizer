# dsh-optimizer —— 优化插件集

**把省 token 的开关收在一个「优化」面板里。** 输入栏右侧（模型选择器左边）一个「优化」图标，
点开是开关面板；再点图标 / 按 Esc / 点面板外收起（面板头部没有 ✕，收起就这三种）。开关改动的**下一个模型步骤**就生效。

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 推理等级 auto | **开** | 每个请求按轻重自动选推理档位：闲聊与轻活少想，重活多想。落成该模型**真实支持**的档位；模型不支持、目录查不到、判定出错，一律原样透传。**你在模型选择器里手选的档位永远优先。** |
| 并行工具调用 | **开** | 在系统提示词里加一段纪律：互不依赖的工具调用必须放进**同一条消息**。宿主本来就会并发执行同一组调用，缺的只是让模型这么做——每合并一次就省掉一整轮请求（也就是重发一遍全部上下文）。 |
| 失败重放 | **开** | 工具调用因参数错失败后，只发 `{\"patch\":{出错的字段:新值}}` 就能重放，不必把原来那一大坨参数整个重新生成。失败结果后面还会挂一行提示，点名是哪几个字段出错。 |
| 工具结果上限 | **开** | 超过 8192 字符的工具结果，在**写进会话之前**截头留尾，全文落到 `<DSH_HOME>/optimizer-spill/`，结果里带路径。宿主自己的上限是 12500 token（约 5 万字符），这里更紧一档。 |
| 不动已发内容 | **开** | 把上限压到内置裁剪器（`tool-result-pruner`，8192 字符）的阈值以下，并**连 `read` 一起裁**——让它下一次压缩时找不到可裁的结果。已发出去的上下文因此永不被改写，供应商的前缀缓存不会从中间断掉。 |
| 复读抑制 | **开** | 连着两轮"没有工具调用、也没有新内容"的助手输出（例如反复"Let me do it""好。"）就插一条提醒；连到 4 轮直接停住这一步。带工具调用的消息一律清零。 |
| 按需加载工具说明 | 关 | 默认只把核心工具的 schema 发出去，其余留一个 `load_tools` 索引，用到再取。省下固定常驻成本，代价是工具表变化处会重建一次前缀缓存。 |
| 提前自动压缩 | 关 | 宿主的自动压缩线是 **678,464** token。打开后越过 30 万就主动压一次，不必等历史涨到 67.8 万。默认关闭：压缩会花一次摘要调用并改写历史。 |
| 按任务换档 | 关 | IM 闲聊这类轻活切到更便宜的模型/更低的推理档。只走官方 `agent/request` 瀑布；映射默认留空（= 不换），**手选优先**。 |
| 精简化输出 | 关 | 在系统提示词最后追加一段输出纪律：零开场白、零复述、零装饰性小节，只留事实、代码、命令、路径、风险与下一步。**任务内容一个字不改。** |
| 花费预警 | 关 | 本会话花费到你在开关标题后面填的预值（元）就**停住这一轮**，弹出弹窗。要继续得先把弹窗上那六位随机数字照着敲一遍；选"终止任务"就是停手，并把本会话最初的提示词摆回来给你看。**填一个正数会自动打开这个开关**（填 `0` 不会）。**每个会话各填各的，互不影响。** |

以后新增省 token 的开关，按下面"加一个开关"那节实现同一个约定即可进面板。

## 推理等级 auto：判定表

| 组 | 典型输入 | 落到 DeepSeek 四档时 |
| --- | --- | --- |
| quiet | 「你好」「谢谢」这类纯客套，且整句很短 | `off` |
| light | 提问、解释、看文件、总结 | `low` |
| standard | 改代码、转格式、写脚本、排查报错 | `high` |
| heavy | 架构设计、整套重写、全面审查 | `max` |

档位更少的模型自动合并：三档（low/medium/high）→ 轻活到中档、中活与重活共享顶档；
两档（low/high）→ quiet/light 走低档、standard/heavy 走高档。档位与组无关，只看该模型
**声明支持**哪些；一个都不支持就完全不动。

短追问（「继续」「那这个呢」）继承上一轮的组，且重活不会被继承成轻活。

### 分数怎么来的

信号分相加，再加一档长度分，最后落组：`0` → quiet；`1~2` → light；`3~8` → standard；
`9+` → heavy。

| 信号 | 分 | 例子 |
| --- | --- | --- |
| 客套（排他） | 0 | 整句只有「你好」「谢谢」「可以可以」且 ≤8 字 |
| 提问 | 2 | 什么是…、为什么…、…吗？ |
| 要动手 | 2 | 帮我改、实现、部署 |
| 转格式 | 3 | 把 X 转成 Y、删掉、重命名 |
| 要读/要看 | 1 | 看看、检查、审查、总结 |
| 出问题 | 3 | 崩溃、报错、异常、内存泄漏 |
| 大工程 | 6 | 架构、从零、整套重写、性能瓶颈、安全审计 |
| 要"做到最好" | 3 | 极致、完美、最优、全面、逐项、字斟句酌 |
| 要验收 | 2 | 验收、核对、逐条、边界情况、跑通 |
| 有交付后果 | 2 | 交付、上线、发布、给客户、生产环境 |
| 权衡判断 | 1 | 要不要、该不该、优缺点 |
| 锚点（路径/URL/技术词/代码符号） | 1 各 | `src/a.ts`、https://…、接口、`foo()` |
| 拿不准 | 1 | 不确定、可能、随便 |
| 长度｜≥21 字 | 2 | 那一档的含义是"这不是一句客套" |
| 长度｜≥200 字 | 6 | 只取最高一档，不叠乘 |
| 长度｜≥800 字 | 10 | 同上 |

`scoreText(text)` 单独导出，权重表由测试直接钉住——改权重先看分数，再看组。

## 为什么省 token 而不伤质量

- **精简化**：提示词段落是"生成前约束"，不是"生成后裁剪"。模型写文件、跑命令、装文档时
  走的路与不装插件时完全一致，被省掉的只有它本来会写、而你没在看的那些字。关闭时返回
  空串，宿主把整段丢掉——**关掉就是零成本**。
- **推理等级**：省下来的是**思考预算**，不是任务本身。轻活本来就不需要长推理；判错成重活
  只是多花一点思考。判错成轻活的风险用两条规则兜住：(1) 要动手、要读东西的活最省也停在
  `low`，不会被压到 `off`；(2) 出现出问题 / 大工程 / 极致类要求时分数直接把档位抬上去。
  判定是纯字符串规则，每个 turn 跑一次，微秒级，**不额外发请求、不额外花 token**。

## 它挂在哪儿（以及刻意不挂哪儿）

推理等级只挂两个宿主公开的契约事件：

- `agent/pre-step` —— 每个 turn 的起点，拿这一步真正要进模型的用户消息判组；
- `agent/request` —— 拿这次调用的完整配置，写回 `reasoningEffort`。

两者都是"读参数、调 `next()`"的形态。**不包任何模型调用路径、不改模型目录、不改模型
选择器的 DOM**——早期版本正是这些做法把宿主内存拖爆的。

### 1. 并行工具调用：宿主早有机制，缺的是纪律

宿主 `dsh-agent-loop` 的 `executeToolCalls` 会把同一条助手消息里、声明了
`isConcurrencySafe` 的调用**并发**跑（上限 10），结果按模型顺序落库。所以问题不在宿主，
在于模型习惯"一步只发一个调用"——而每多一步，就要把**整个上下文重发一遍**。

本插件因此**不加工具**（加工具等于每轮多背一份 schema），只在系统提示词里加一段纪律，
用"必须"和具体例子（多个 read、read+grep+glob、多个 bash 探针）把它说死，并点明唯一
例外：后一个参数真的来自前一个结果时才串行。

### 2. 失败重放：只发改动的字段

参数错时模型看到的只有一行 `Error: invalid arguments: missing required property "path"`。
要重试，它只能把原来那一大坨参数**整个重新生成**。本插件的做法：

1. `tools/post-execute` 里把失败的 `(name, arguments)` 记下来，**有界**：每个 agent 最多
   3 条、参数超过 4KB 不记、最多跟踪 64 个 agent，只存字符串；
2. 失败结果后面追加一行 ≤160 字符的提示，点名是哪几个字段出错；
3. 注册 `retry_tool`：`{"patch":{...}}` 合并进原参数（对象深合并、`null` 删字段）、
   `{"args":{...}}` 整体替换、`{"name":"..."}` 指定更早的一次失败；
4. 重放走宿主自己的 `tools.execute()` —— 完整经过 `pre-execute`、审批、`post-execute`，
   不绕开任何一道闸门。`retry_tool` 不能重放自己。

### 3. 工具结果上限 + 落盘：把裁剪提到发送前

宿主已经有 `dsh-spill-policy`（12500 token 上限，约 5 万字符）和
`tool-result-pruner`（压缩时把超过 8192 字符的结果改成 head 4096 + tail 1024）。前者
在发送前，后者**改的是已经发出去过的结果**。

本插件把同一件事再提前、再收紧一档：`tools/post-execute` 里超过 8192 字符的文本结果
截头留尾，全文写进 `<DSH_HOME>/optimizer-spill/<会话>/<调用>.txt`，结果里带路径与取回
方法。模型要细节就自己 `read`（带 offset/limit）或 `grep`，只把真正需要的那一段拉进来。

实测（6 条真实形状的素材，见 bench）：50180 → 6927 字符、88769 → 6925、60007 → 6931……
平均省 **83.5%**，且每一条的全文都能逐字节回读。

### 4. 不动已发内容：让内置裁剪器无事可做

供应商的前缀缓存是按"前缀逐字节相同"命中的。任何对**已经发过**的内容的改写，都会让
缓存从改写点开始全部失效，后面的 token 全部按未命中计价。`tool-result-pruner` 就是
这样工作的：压缩时追加一条影子事件把老结果换掉。

本插件的应对是算术意义上的：把上限压到裁剪器的阈值以内（默认 8192 = 裁剪器的
`thresholdChars`），并且**连 `read` 一起裁**（`read` 自己有 `readMaxBytes = 50KB`，
不裁的话它仍会被裁剪器改写）。改完之后，裁剪器下一次压缩时找不到任何一条超阈值的结果。

面板的自检数字会实时显示"裁剪器阈值 / 本插件实际上限"，两者不匹配时一眼能看出来。

### 5. 复读抑制：连续碎片才算，正常收尾不误伤

`session/event` 上只看 `assistant/message`，判定口径刻意窄：

- 带工具调用的消息 → 连击**清零**（哪怕正文只有一句 "Let me read it"）；
- 纯文字且短于 30 字符，或归一化后与上一条完全相同 → 连击 +1；
- 其余（正常长度的回答）→ 清零。

连到 2 条插一条提醒（只提醒一次，插完把连击压回 1，不会每个 step 都插）；连到 4 条
返回 `{kind:'reject'}` 停住这一步——这是宿主 `agent/pre-step` 的正式返回值，不是取消。

### 6. 按需加载工具说明：藏 schema，不藏工具

在 `system-prompt/assemble` 瀑布里改写 `assembly.tools`。这个瀑布每轮重新跑、返回值
权威，而且**只影响"模型看见什么"**：工具注册表没动，隐藏的工具按名字照样可调用。

- `load_tools({"list": true})` → 一行一个工具的索引（名字 + 96 字符描述）；
- `load_tools({"names": ["a","b"]})` → 从下一步起这几份 schema 进工具表。

已解锁集合用 `WeakMap` 挂在 agent 对象上，agent 被回收时记录跟着走。默认核心集是
`load_tools / read / write / edit / glob / grep / bash / todo_write / ask_user_question`。

实测（13 个真实形状的工具）：每轮 schema 25,676 → 5,832 字符，**净省约 1,061 token/轮**。
代价写在明面上：工具表变化处，宿主会记一条 `tool-addition`，供应商前缀缓存从那一点起失效。

### 7. 提前自动压缩：把 67.8 万这条线挪下来

用户说的"约 67.8 万"是准的，只是它不是代码里的字面量，是四个默认值乘出来的：

```text
min(1e6 × 0.8, 1e6 − 256e3 − 65536) = min(800000, 678464) = 678464
```

本插件把同一条式子复算一遍（好知道宿主的线在哪），再和用户设的线（默认 300,000）比。
**只有用户线低于宿主线时才自己动手**；一旦越过宿主线就交给宿主，绝不两边抢着压同一个
会话。另有 120 秒冷却，防止连环压。压缩调的是宿主的 `compaction.compactNow()` ——
和 `/compact` 命令同一条路。

### 8. 按任务换档：只走官方瀑布，手选优先

`agent/request` 是文档里写明**唯一**能在派发前替换 `LlmCallConfig`（provider / model /
reasoningEffort）的钩子。用它，不碰模型目录、不碰选择器、不包 `llm.stream`。

两条硬约束：

1. **没有映射就不换**。这一版运行时的模型目录里**没有任何价格字段**（只有
   `contextWindow` / `maxTokens` / 描述），凭 id 猜"flash 比 pro 便宜"不可靠。所以只在
   `cordis.patch.yml` 里明确写了 `tierModelQuiet: 供应方/模型` 时才换。
2. **手选优先**。会话里出现 `model/selection` 事件（用户在选择器里点过模型）之后，
   这个会话永久跳过换档。

### 与宿主既有机制的关系（别重复记功）

| 宿主已有 | 本插件的关系 |
| --- | --- |
| `dsh-spill-policy`（12500 token 上限，发送前落盘） | 本插件更紧一档（8192 字符），两者不冲突；本插件的裁剪先发生，宿主那边就没得可裁 |
| `dsh-compaction-tool-result-pruner`（压缩时改写历史） | 本插件用"发送前裁到线内"让它在算术上无事可做 |
| `dsh-repeat-tool-reminder`（同一个工具+同一份参数连续调用 3/5/8 次） | 管的是**工具重复**；本插件管的是**文字空转**，两者互补 |
| `dsh-compaction-basic` 的自动压缩（678,464） | 本插件只是把线提前，越线后仍然交给它 |

## 开关长什么样（美术风格）

面板里的开关是本插件自己画的（只 `require('react')`，拿不到内置控件），但**度量与配色
一律对齐内置开关**（`ui-primitives` 的 `Switch.module.css`）：

| 项 | 值 |
| --- | --- |
| 轨道 | 36×20，`padding: 2px`，`border-radius: 999px` |
| 滑块 | 16×16 正圆，打开时 `translateX(16px)` |
| 关→开 底色 | `--dsw-alias-border-l3` → `--dsw-alias-brand-primary` |
| 滑块色 | 关：`--dsw-alias-switch-thumb`；开：`--dsw-alias-label-primary-foreground` |
| 焦点环 | `--dsw-focus-ring-width` + `--dsw-focus-ring-color`（回落到 `--dsw-alias-state-business-primary`） |

两处容易漏掉、漏掉就"看起来不是一套东西"的细节：

1. 开关本体必须是 `<button>` 才能键盘切换，所以 `appearance / margin / padding / border /
   box-sizing` 都要显式清掉，否则浏览器会给它自己的描边与内边距。
2. 应用会给控件做全局**超椭圆圆角**，内置开关用 `corner-shape: round` 明确退出。手写的
   轨道与滑块也必须写这一条，否则胶囊和圆点的形状与内置开关不一致。

`test/client.test.js` 里有一条用例把上表的数字逐条钉住，改样式改歪了会当场失败。

## 花费预警：怎么算、怎么拦、怎么放行

| 环节 | 做法 |
| --- | --- |
| 算钱 | 只折叠三种会话事件（`assistant/message`、`assistant/attempt`、`llm/retry-started`），别的原样返回。金额是**微元整数**（`元/百万 token × token`），不漂移。 |
| 价目 | 内置 DeepSeek 官方价目表（与 `dsh-session-cost` 逐条一致）：flash 档 `0.02 / 1 / 4`，pro 档 `0.15 / 4.5 / 13.5`（元每百万 token，命中 / 未命中 / 输出）。工作日 9:00–12:00、14:00–18:00（北京时间）按高峰价，周末与法定节假日按空闲价。 |
| 金额单位 | 内部一律用**纳元**（1 纳元 = 1e-9 元）整数。预值走十进制字符串解析（`toNanos`），所以 `0.0001` 这种小预值不会被浮点或舍入吃掉；最小可表示 1 纳元，比 DeepSeek 最便宜的一笔（1 个命中缓存 token = 0.00000002 元 = 20 纳元）还小一档。 |
| 会话隔离 | 预值、累计花费、拦截状态**全部按会话 id 记**，一个会话一个额度、互不影响。面板读/写预值都带 `sessionId`；不带会话的写入被拒（`400`），绝不回退成一个"全局额度"去拦别的会话。预值不落盘：会话关掉（或宿主重启）就回到 `costLimitDefault`，重新填一次即可。 |
| 拦 | `session/event` 上判定（**花费只在那里变**），越线立刻调宿主自己的 `agent.cancel({ kind: 'hook' })`——和停止键同一条路，且不带 `keepInbox`，队列里排着的活儿一起停。`agent/pre-step` 只做兜底：已经拦下的会话不会靠下一条消息偷偷续跑。 |
| 放行 | 弹窗上的六位数字**每拦一次抽一组**（`hits` 变了才换），六格分开填，填对才点亮"继续任务"。放行时宿主给模型下一条"按原要求从停下的地方继续"的消息，**推理等级一个字都不动**；同时**放行这一步**（否则下一步又会被预值拒回去，看着像"点了没反应"）。再花超了会重新拦——放行不是永久解除。 |
| 终止 | 红色"终止任务"按钮。宿主做两件事：①停手（顺带停掉队列里排着的活）；②把本会话**最初的提示词**原样摆出来给用户看。**不给模型下达任何指令**——不删文件、不派收尾。<br>**终止之后这个会话是停住的**：再发消息也不会跑（`agent/pre-step` 会挡）。要接着用，去面板里把预值调宽或关掉花费预警开关——那是两个明确的解除口。 |
| 弹窗不出现怎么办 | 弹窗状态走两条通道：会话投影（推送）+ `GET ?guard=1&sessionId=…`（1.2 秒轮询）。连续三次问不到宿主时，页面右下角会挂一条**红色告警**，而不是安静地什么都不做。若既没弹窗也没告警，检查：这个会话的预值是否 > 0、`costGuard` 开关是否开着（填正数会自动开）、以及宿主是否已重启加载新代码。 |
| 弹窗的两条来源 | 弹窗状态走**两条通道**：会话投影（推送）与 `GET ?guard=1&sessionId=…`（2 秒轮询兜底），谁新听谁的。单靠投影时，一旦推送没送到，弹窗就永远不出现——"装了跟没装一样"。 |
| 没有随手关掉的路 | 弹窗上**只有两个按钮**：「继续任务」（填对六位数字才可点）与红色「终止任务」。没有 ✕，`Esc` 与点遮罩都不放行，也没有"顺手改预值"的旁路——越线时就是要拦住人，能一键划掉就等于没拦。要离开只有两条路：验证通过继续，或者终止。所有请求 8 秒超时，按钮不会卡在"正在…"。 |
| 改预值 | 把预值改大就自己松开——判据变成新预值，不需要额外的"取消拦截"接口。开关关掉同理。面板里改完**不用按 Enter**：失焦、按 Enter、点面板外面、点图标收起、按 Esc 都会把它写回宿主。 |

认不出的模型（不在价目表里）**不计价也不拦**，只如实记下有多少 token 没算钱（弹窗里会显示）。

## 代价：一次前缀缓存失效

精简化段落恒定在提示词末尾，开关不变时逐字节稳定，不产生额外缓存失效。只有你**主动**
拨开关的那一次，会从这一段起重新计费一次。推理等级改的是请求头里的档位字段，不动提示词。

## 诊断端点

| 方法 | 作用 |
| --- | --- |
| `GET /dsh-optimizer` | 三个开关状态、开关登记表、预值、生效配置、装配统计 |
| `GET /dsh-optimizer?diag=1` | 追加：每轮判定次数、组分布、最近 20 条落地记录、在记会话数、拦截计数、预值（纳元）、`staleLimit` 提醒 |
| `GET /dsh-optimizer?sessionId=<id>` | 本会话的预值（面板回读它；不带就返回 0） |
| `GET /dsh-optimizer?guard=1&sessionId=<id>` | 该会话的金额 / 预值 / 拦截状态 + 最初的提示词（弹窗读它） |
| `POST /dsh-optimizer { "auto": boolean }` | 推理等级开关 |
| `POST /dsh-optimizer { "enabled": boolean }` | 精简化开关（兼容旧字段名 `concise`） |
| `POST /dsh-optimizer { "costGuard": boolean }` | 花费预警开关 |
| `POST /dsh-optimizer { "costLimit": 5, "sessionId": "…" }` | 该会话的预值（元，可小数；`0` = 不限）；非法值 `400`，缺 `sessionId` 也是 `400` |
| `POST /dsh-optimizer { "guardAction": "continue"\|"terminate", "sessionId": "…" }` | 弹窗的两个答复 |
| 其它方法 | `405`；坏请求体 `400` |

`diag=1` 是排查"到底生效没生效"的唯一入口：`effort.recent` 里每条 `apply` 记录都带
`bucket` / `model` / `from` / `to`。

## 加一个开关 = 不用改这个插件一行代码

面板从 `GET /dsh-optimizer` 的 `switches` 字段读登记表，每项描述一个开关：

```json
{ "id": "concise", "label": { "zh": "精简化输出", "en": "Concise output" },
  "hint": { "zh": "…", "en": "…" }, "endpoint": "/dsh-optimizer", "field": "enabled" }
```

`field` 决定读哪个字段，所以一个端点可以挂多个开关（本插件三个开关就是这样共存的）。
条目上还可以带一格可选数字框：

```json
{ "input": { "field": "costLimit", "unit": { "zh": "元" }, "placeholder": { "zh": "预值" },
  "hint": { "zh": "…" } } }
```

读不到（没装、404、返回垃圾）的开关直接不显示，不会出现"点了没反应"的项。

## 失败方向

| 情况 | 行为 |
| --- | --- |
| 模型不支持推理 | 不改，透传 |
| 模型目录取不到 / 抛错 | 不改，记警告（目录缓存 1 分钟后重试） |
| 判定或写回时抛异常 | 不改，透传，计数 +1 |
| 提示词段落名字被占用 | 只丢段落，推理等级照常工作（注册类动作全部经过 `guard()`） |
| 端点注册失败 | 没有开关面板，判定与落地照常 |
| 状态文件读坏 | 保持默认值，记一条警告 |
| 状态文件写不进 | 只记警告，内存值照旧 |
| 花费预警没开 / 预值填 0 | 完全不动这个会话，一行日志都不打 |
| 只填了预值、没点开关 | 填正数会**自动**把开关打开，不存在"填了却不拦" |
| 面板里改完预值就走 | 关闭面板会先把没提交的数字写回去（关闭会卸载输入框，浏览器不补发 blur） |
| 预值写入被宿主拒绝 | 面板当场显示原因（如"宿主认不出这个会话"），**不静默失败** |
| 会话是子代理 / 已归档 / 没有活 agent | 预值只认会话 id，照样填得上、照样拦（唤醒那条路才需要活着的 agent） |
| 同一会话的不同 Session 实例 | 一切按**会话 id** 认，不按对象身份——同一场会话永远算同一场 |
| 盘上还是旧单位的预值键 | 新代码不读它（`?diag=1` 的 `staleLimit: true` 会提醒），重新填一次预值即可 |
| 模型不在价目表里 | 不猜价、不拦，只如实记下未计价 token |
| 会话没有活着的 agent | 记下状态并提示；下一次 `agent/pre-step` 仍会拦 |
| 花名册满了（64 个会话） | 淘汰最旧的，绝不淘汰"正在拦的" |

**不会让模型收到半截指令，也不会让宿主拒绝启动。**

## 已知边界

- 自动档位不写回模型选择器，界面上显示的仍是那个会被改写的档位；真实生效值以会话日志
  里的 `request/header` 或 `?diag=1` 的 `recent` 为准。
- 会话中途重启插件时，第一轮按"用户手选优先"保守处理（那一轮不动档位），之后恢复。
- 每个会话一条判定记录（只存组名与档位 id，上限 64 条），会话销毁即释放。
- 花费预警拦在**一次模型请求结算之后**：越线那一刻已经花掉的钱会照付，拦的是"下一步不再
  继续花"。要更早刹住只能砍预算本身。
- 预值单位从 4.0 的"微元"换成了"纳元"，并且改成**按会话**保存（4.0 的 `costLimit` /
  `costLimitNanos` 两个键都不再被读）。升级后请在面板里重新填一次预值：每个会话各填各的，
  宿主重启后也需要重填。旧键留在文件里不会被读，`GET /dsh-optimizer?diag=1` 会给
  `staleLimit: true` 作为提醒。
- 预值不落盘是刻意的：把"每个会话的额度"持久化收益很小，而读串会话（拿到别人的额度）很难查。
- 预值只认**会话 id**：填的时候不需要那场会话有活着的 agent（子代理会话、已归档会话都行）。
  只有"继续任务"（要唤醒模型）才需要 agent，那时会话没活着会在弹窗里说清楚。
- 弹窗**不能随手划掉**（这是明确要求）：✕ / `Esc` / 点遮罩都不放行，也没有改预值的快捷按钮。
  要离开只有两条路：填对验证码继续，或按终止任务。宿主端点如果整段时间问不到，弹窗本体也
  不会出现——那时页面右下角会有红色告警。
- 终止是**真停住**：终止之后这个会话不会再跑，直到用户在面板里把预值调宽、或关掉花费预警
  开关（这两个动作都会立刻解除）。这样"终止"才有意义——早先只停当前一轮，用户再发一条消息
  模型就又跑起来，那不是终止。
- 金额与 `dsh-session-cost` 面板上的数字同源同口径，但**各算各的**：两个插件都装了也不会
  互相干扰，缺任何一个也都能单独工作。价目表改价时两边都要跟着改。
- 终止任务**不删任何东西**，也不给模型下指令：它只停手并回显本会话最初的提示词。
  写到一半的产物留在磁盘上，删不删、怎么删由用户自己决定（插件不替用户做破坏性动作）。

新十项优化的边界，逐条说清楚（**没做到的不假装做到了**）：

- **并行纪律是"让模型做"，不是"强制模型做"**。宿主只在模型**已经**把多个调用发进同一条
  消息时才并发；插件没有办法把一条消息拆开或合并。所以这一项的收益取决于模型听不听话，
  实测口径是一个估算（见 bench 里标 `computed` 的三行）。
- **失败重放只在"参数错"这类失败上划算**。工具名不存在、参数不是对象、参数超过 4KB、
  或失败发生在 `retry_tool` 自己身上时，一律拒绝并说明理由——那时模型只能走原来的路。
- **结果上限会改变模型看到的东西**。全文在盘上、路径在结果里，但如果模型不去读，它就
  只有头尾。所以落盘失败时**不裁剪**（宁可多花 token，也不给一个取不回来的残缺结果）。
- **`cacheSafe` 打开时 `read` 也会被裁到 8192 字符**。这是"让裁剪器无事可做"的必要条件
  （`read` 自己封顶 50KB，比裁剪器阈值大）。要看大文件请用 `offset`/`limit` 分段读，或
  读落盘的那份全文。
- **按需加载的索引只在调用 `list` 时进上下文**，不是每轮常驻。但工具表变化处会产生一条
  `tool-addition`，供应商前缀缓存从那一点起失效——这是这一项默认关闭的原因。
- **提前压缩的"省"是推算**：需要"会话会跑多少轮、每轮多大"这些本机没有的事实。bench 把
  假设与算式都写出来了（默认线 30 万、宿主线 678,464、压缩后保留约 119k）。
- **换档不做自动挑模型**。这一版运行时的模型目录里没有价格字段，凭 id 猜便宜不可靠；
  没在配置里写映射就一分钱不换，也一分钱不省。手选过模型的会话永久跳过。
- **没有任何一处包住模型调用**：不挂 `llm/stream`、不改模型目录、不碰模型选择器。
  挂的全是 `systemPrompt.section` / `system-prompt/assemble` / `tools.post-execute` /
  `tools.register` / `session/event` / `agent/pre-step` / `agent/request`。
  测试里有一条专门断言这件事（"没有包住模型调用的钩子"）。
- **跨调用状态全部有界**：失败记录每 agent 3 条 × 64 个 agent；复读窗口每会话 6 条 ×
  64 个会话；已解锁工具用 `WeakMap` 挂在 agent 上；只存字符串与数字，不持有请求对象、
  消息数组或结果对象。
